5/23 fixing loss ablations and adding slurm scripts
=== start of notes === 
problem: loss vals from vgg terms are HUGE (1e9)

claude:
Root cause is l_style in phase1_mirror_map/losses.py. The Gatys
 normalization ||Gg − Gr||²_F / (4·C²·H²·W²) leaves per-layer style loss
 scaling as O(activation⁴): each Gram entry is Σ_{HW} F_i F_j = O(M·a²),
 squared and summed over C² entries gives O(C²·M²·a⁴), and the denom
 4·C²·M² cancels everything except O(a⁴). With ImageNet-normalized
 Sentinel-2 RGB and VGG-19 ReLU activations of O(10–100), l_style ≈ 1e7;
 times style_weight=100 → ~1e9, swamping cycle (~24), recon (~0.5), and the
 spectral terms (~0.5).

 Other terms are already in compatible ranges: l_dis (Gaussian-kernel MMD) is
 bounded in roughly [-2, 2]; l_recon, l_sam, l_moments are all O(1) on
 [0, 1] reflectance.

 Effect on the ablation: in vgg / full runs the gradient is dominated by
 VGG style, so any signal from L_sam / L_moments / L_recon is invisible
 and cross-family val-loss ranking is not meaningful.

fix: Replace the Gatys denominator with a per-layer relative-error formulation:

 L_style = Σ_l  w_l · ||G_gen^l − G_ref^l||²_F  /  (||G_ref^l||²_F + eps)

 Both numerator and denominator are O(a⁴), so the ratio is invariant to VGG
 activation magnitudes, feature-map size, and input distribution. At
 initialization it sits near O(1) when Gen and Ref Grams are dissimilar; goes
 to 0 as they match (preserving the existing "zero on identical inputs"
 property the unit tests check). Same semantic intent as Gatys — match
 channel co-activation patterns — just unit-free.

 gram_matrix stays as the raw F F^T; normalization is l_style's job.

constr=nan fix (losses.py):
problem: training logs showed constr=nan and loss=nan from step 0 for all 600+ steps,
meaning weights were NEVER updated (GradScaler skips optimizer.step when grads are nan)

root causes:
1. fp16 overflow in VGG gram matrices: f_psi at init outputs ReLU(decoder + y_noisy)
   where y_noisy = g_phi(x) + sigma*z. g_phi at init can produce large values, so
   y_noisy is not bounded to [0,1]. a pixel value of 40 becomes ~172 after ImageNet
   normalization (std~0.2). Gram entry = sum_hw(f_c1 * f_c2) ~ 172^2 * H * W which
   blows past fp16 max (65504) -> NaN immediately
2. l_style magnitude explosion: even in float32, Gatys l_style ~ 1e7/layer, at
   style_weight=100 contributes ~1e9 to loss vs cycle~24 and spectral~0.5 (7-8 orders
   of magnitude imbalance). prevents any gradient signal from non-VGG terms
3. VGG receiving out-of-range inputs: reflectances should be [0,1] but f_psi output
   is unbounded above 1.0 at init

fixes in losses.py:
- VGGFeatureExtractor.forward: x = x.float() at start (upcast from fp16 before gram)
- VGGFeatureExtractor.forward: .clamp(0.0, 1.0) on RGB bands before ImageNet norm
- l_style: replaced Gatys formula with cosine-distance (unit-Frobenius-normalise both
  Grams before differencing). result is bounded in [0, 4] regardless of activation
  scale. Gram-magnitude info already captured by l_recon and l_moments

# 6/3 train_mirror_diffusion.py — phase 2 standard EDM in mirror space

switched from EMRDM residual bridge to standard (non-residual) EDM:
- EMRDM residual bridge broken in mirror space: mean_key="S2" is cloudy in reflectance space
  but target="target" is g_phi(clean) in mirror space -> bridge interpolates two different spaces,
  model just learns to output near-zero (the compressed mirror range) and ignores conditioning
- fix: standard EDM, no mean_key, starts from Gaussian noise, conditioned on S1S2
- new script: phase2_emrdm/train_mirror_diffusion.py
- uses g_phi on-the-fly (no pre-saved mirror images needed); pkl files from eval_emrdm.py

mirror data stats (from check_mirror_range.py):
- global range: [-0.174, 0.296], mean=0.003, std=0.033, no NaN/Inf
- sigma_data=0.033 (set to match empirical std of mirror targets)
- sigma_max=5.0 for inference (within training log-normal: exp(P_mean+2*P_std)=exp(2.4)~11)
  original sigma_max=80 from EMRDM paper (for data std~0.5) caused pure noise output

dataset fix — 12K -> 98K training samples:
- old pkl files were generated from only a subset of data (spring only, ~17K triplets total)
- diagnose_dataset.py confirmed all 4 seasons have 100% regex match: 122,218 matched triplets
- fix: regenerate pkl files with build_triplets()+write_pkl_files() on all seasons
- train: ~98K, val: ~12K, test: ~12K

training improvements added:
- AdamW weight_decay=1e-4 (was Adam, no weight decay -> overfit at epoch 28 on 12K data)
- CosineAnnealingLR from lr=1e-4 to lr/10 over epochs (prevents late-training oscillation)
- EMA decay=0.999 (shadow weights for inference; validation runs under EMA weights;
  checkpoint saves both raw and EMA state under "ema" key)
- run_mirror_diffusion.py loads EMA weights automatically if present in checkpoint

NaN loss during training (mirror_edm_final2, ep019 step 07800):
- same root cause as EMRDM NaN: rare tail sigma from log-N(P_mean=-1.2, P_std=1.2)
  e.g. sigma~0.001 -> EDM weight = (sigma^2+sd^2)/(sigma*sd)^2 ~ 160K with sd=0.033
- GradScaler skips the NaN step automatically so training may recover
- if NaN becomes permanent, apply these two fixes in edm_loss() in train_mirror_diffusion.py:
    weight = weight.clamp(max=1.0 / sd**2)   # cap at ~918 for sd=0.033
  and in the training loop after loss.backward():
    if not loss.isfinite(): optimizer.zero_grad(); scaler.update(); continue

visual results at epoch 10 (98K dataset, mirror_edm_final2):
- major improvement over 12K runs: real cloud removal happening, natural colours,
  rivers/coastlines/urban grids visible, no blue cast
- remaining issues: grainy texture (needs more epochs), heavy cloud cases still hard
- expected to improve further toward epoch 50-100

S2 dropout for heavy-cloud robustness (--s2_dropout 0.15):
- added to edm_loss() in train_mirror_diffusion.py
- per-sample: 15% chance of zeroing cloudy-S2 channels (ch2-14) while keeping SAR (ch0-1)
- forces model to learn cloud removal from SAR alone on those steps
- result: heavy-cloud outputs improved significantly; urban/terrain structure recovered well

vegetation colour fix — cloud-weighted dropout:
- problem: uniform 15% dropout also dropped S2 on clear-sky patches where S2 was accurate,
  biasing the model against using S2 for vegetation spectral information (high-NIR/low-red
  signature). result was vegetation appearing brownish/purplish instead of green.
- fix: scale dropout rate by per-patch cloud coverage proxy (mean blue band brightness):
    cloud_weight = (blue_band / 0.3).clamp(0.0, 1.0)
    effective_rate = s2_dropout * cloud_weight
  blue band (B02, ch2 of s1s2) is high for clouds (~0.5-0.8), low for clear sky (~0.05-0.15)
- effect on effective dropout rate per patch type:
    dense forest (clear): 2.6%  <- almost never dropped, spectral signal preserved
    partial cloud:       12.4%  <- mostly dropped, SAR robustness active
    heavy cloud:         15.0%  <- full dropout rate
- clear-sky vegetation patches almost never lose S2 -> green spectral signature learned correctly
- heavily cloudy patches still get full SAR-only training -> robustness preserved
